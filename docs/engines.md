# Рушії: план робіт

Записано 28.10.2026. Ідея — у `docs/concept.md`; тут — що в якому порядку робиться і що вже зроблено.
Тексти інтерфейсу й описи нейтральні: кажуть, що програма робить, і ніколи — де працює рушій.

## Фаза 0 — шов для другого рушія розшифровки

> **Зроблено 28.10.2026.**

Модель і воркер виїхали з `App.tsx` у `src/useWhisper.ts`. Назовні — стан моделі (для рядка статусу, вікна
згоди й налаштувань) і `transcribe(samples, language, handlers)`, що повертає `Promise<{ text, segments } | null>`
(`null` — прогін зупинено або GPU впав, і повідомляти нема чого). `App.tsx` тримає тільки сам прогін: читання
звуку, `job`, текст, продовження після зупинки. Хмарний рушій у фазі 2 дає ту саму сигнатуру `transcribe`.

## Фаза 1 — конспект і таймкоди через API

> **Зроблено 28.10.2026.**

- Один адаптер: OpenAI-сумісний `POST {baseUrl}/chat/completions`. Покриває OpenAI, OpenRouter, Groq,
  ollama, LM Studio, llama.cpp, vLLM. Чисті функції — `src/api.ts` (тест `src/api.test.ts`), запит — `net.fetch`
  у main (`src/summary.ts`), тож `ai:run`, промпти й скасування ті самі.
- Налаштування рушія живуть у main (`engines.json` у `userData`), не в localStorage. Ключ шифрується через
  `safeStorage` і назад у renderer не йде — той знає лише «ключ є».
- Зміна Base URL стирає збережений ключ: інакше renderer міг би перенаправити чинний ключ на чужу адресу.
- Без системного сховища ключів (`safeStorage` на `basic_text`) ключ не зберігається взагалі — помилка, а не
  тихе збереження відкритим текстом.
- `https` обов'язковий; `http` — лише для `localhost` / `127.0.0.1` / `[::1]`.
- За замовчуванням лишається `claude` CLI; API вмикається явним вибором у налаштуваннях.

## Фаза 2 — розшифровка через API

> **Зроблено 28.10.2026.**

- Той самий адаптер: `POST {baseUrl}/audio/transcriptions`, multipart, `response_format=verbose_json`. Запит —
  `src/speech.ts` у main, через спільний `postApi` (`src/apiRequest.ts`), яким ходить і конспект: ключ, таймаут,
  `redirect: 'error'`, тексти помилок і скасування в одному місці.
- Сегменти з таймкодами (перевірено в документації 28.10.2026): OpenAI `whisper-1` — так; `gpt-4o-transcribe` і
  `gpt-4o-mini-transcribe` — лише `json`, без таймкодів; Groq `whisper-large-v3` / `-turbo` — так. OpenAI
  вимикає `whisper-1` і всі `gpt-4o-*-transcribe` 26.02.2027, а новий `gpt-transcribe` таймкодів не документує
  (перевірено 28.10.2026) — тому OpenAI в пресетах розшифровки немає, а Groq і `whisper-1` лишаються доступні
  через «Локально» (будь-яка адреса) до свого вимкнення. Відповідь без
  `segments` — помилка з назвою моделі й підказкою, а не текст без .srt і розділів (`readSegments` у `src/api.ts`).
- Налаштування: «Розшифровка» (модель розпізнавання / API) поруч із «Конспект і таймкоди». Спершу обидва
  API-рушії ділили адресу й ключ; у фазі 3 у кожного своє з'єднання. Командний рядок лишається на Whisper.
- Вхід — ті самі 16 кГц семпли, що й для Whisper (ffmpeg або декодер браузера), тож продовження після зупинки
  працює так само. `splitAtSilence` (`src/pcm.ts`, тест) ріже запис на шматки до 10 хвилин у найтихішій десятій
  секунди серед останніх 30 перед межею; `useApiSpeech` шле їх по одному і зсуває таймкоди на початок шматка.
  Прогрес — за готовими шматками, зупинка обриває запит і пропонує продовжити з кінця останнього готового.
- Кодування шматка в main: Opus 24 кбіт/с через ffmpeg (~1,8 МБ на 10 хвилин), без ffmpeg — WAV 16 біт
  (~19 МБ, під ліміт 25 МБ). Примітка: експорт доріжки (`exportAudio`, 64 кбіт/с) — це ~29 МБ на годину, а не 10.

## Фаза 3 — інтерфейс

> **Зроблено 28.10.2026.**

- Рядок статусу знає про API-рушій: «Розшифровка через API», під ним модель і адреса сервера (так само в «Про
  MagScribe»). Whisper вантажиться й питає про завантаження лише тоді, коли розшифровка йде через нього: на
  старті або коли налаштування перемикають на нього (`active` у `useWhisper`). Помилка Whisper, поки працює API,
  у статусі не показується.
- «Перевірити» в налаштуваннях (`ai:check` у `src/main.ts`): по одному справжньому запиту до збереженого API на
  кожен рушій, що його використовує, тим самим кодом, що й робота, — секунда тиші через `transcribeApi` (заразом
  видно, чи модель дає таймкоди) і коротке повідомлення через `runApi`. Помилка — той самий текст, що показала б
  робота. Неможлива, поки йде прогін: обидва запити ділили б один дескриптор скасування в `apiRequest.ts`.
- Перший запуск: у вікні згоди на модель — згорнутий рядок «Або розшифровувати через API — вставити ключ». Під
  ним та сама форма, що в налаштуваннях (`EnginesSection` з `onSaved`), лише адреса, модель розшифровки й ключ.
  Збереження вмикає API-розшифровку, а клік, що чекав на модель, одразу йде в API.
- Окреме з'єднання (адреса, модель, ключ) для розшифровки й для конспекту: `engines.json` тепер
  `{ engine, speech, apis: { speech, summary } }`. Файл до 0.8.7 (одна адреса, `model` і `speechModel`, один ключ)
  читається як два з'єднання з тією самою адресою й тим самим ключем (`storedApis` у `src/api.ts`, тест), і
  переписується в новому вигляді при першому збереженні. «Нова адреса стирає ключ» — окремо для кожного.
- Deepgram — другий адаптер розшифровки (`speech: 'deepgram'`): `POST {baseUrl}/listen?model=…&smart_format=true
  &paragraphs=true&language=uk` (для «Авто» — `detect_language=true`), заголовок `Authorization: Token <key>`, тіло —
  сирий OGG/Opus (WAV без ffmpeg). Сегменти — речення з `results.channels[0].alternatives[0].paragraphs`
  (`readDeepgram`, тест). Запит понад 10 хвилин обробки Deepgram обриває з 504, тож нарізання до 10 хвилин
  лишається. Спільне — ключ, таймаут, `redirect: 'error'`, помилки, скасування — той самий `postApi`.
- Пресети в налаштуваннях (`src/providers.ts`): підставляють адресу й першу модель, решта моделей — підказки
  в полі (`<datalist>`) з позначкою «дешевша / легша / розумніша», будь-яку іншу можна вписати. Цін у текстах
  немає. Розшифровка: Deepgram (`nova-3`, `nova-2`) і «Локально» — будь-який OpenAI-сумісний
  `/audio/transcriptions`. Конспект: OpenAI, OpenRouter, Gemini, Anthropic, Mistral, ollama, LM Studio (лише
  адреса — id моделей у нього свої) і «Локально». Застереження:
  - Gemini: OpenAI-сумісність у Google досі в статусі beta.
  - Anthropic: свій OpenAI-сумісний шар Anthropic називає «для тестування й порівняння», не довгостроковим
    production-рішенням; id з дефісами (`claude-haiku-5-5`), а в OpenRouter — з крапкою.
  - Mistral: `mistral-medium-latest` у документації прямо не бачили — перевірити «Перевірити» з реальним ключем.
  - xAI свідомо не додано: його `/chat/completions` позначено legacy.
- `errorDetail` читає й помилки цих провайдерів: Gemini — список `[{ error }]`, Deepgram — `err_msg` / `message`.
- Модальні вікна ширші (544 px): у налаштуваннях тепер два блоки з'єднань із пресетами.

Не перевірено наживо: заголовок `Token` із ключем — під Xvfb немає сховища ключів, тож ключ не зберігається
(так і задумано), і mock бачив запити без ключа. Справжні Deepgram, Gemini, Anthropic і Mistral — без ключів.

## Не вирішено

- Нативний Anthropic Messages API (другий адаптер) — поки ні; OpenRouter покриває через OpenAI-формат.
- Чи отримує командний рядок (`--transcribe`) хмарний рушій.
