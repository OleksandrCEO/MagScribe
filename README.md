# MagScribe

Транскрибація відео й аудіо: текст, субтитри `.srt` і таймкоди розділів для YouTube. За замовчуванням —
локально, на твоїй машині.

> **In English.** MagScribe is a local-first desktop app that transcribes video and audio with Whisper
> large-v3-turbo running on your own GPU (WebGPU, wasm fallback). It produces plain text, SubRip subtitles and
> YouTube-style chapter timecodes. The interface speaks Ukrainian and English — it opens in the language of
> the operating system, and the settings window switches it. Linux x86_64; see
> [What leaves your machine](#що-виходить-із-твоєї-машини) for the one feature that is not local.

## Що воно робить

- кидаєш відео або аудіо — отримуєш текст, розшифрований **на цій машині**;
- із того ж прогону — субтитри `.srt` із таймкодами;
- за бажанням — конспект і список розділів («00:00 — Назва») через локальну команду `claude`;
- окремо — витягує аудіодоріжку в OGG/Opus (контейнер, який Telegram грає як голосове).

Інтерфейс — українською або англійською: при першому запуску береться мова системи, далі перемикається в
налаштуваннях.

Текст, субтитри й таймкоди можна виправити просто у вікні перед збереженням: Whisper плутає імена, а назви
розділів інколи варто переписати людською мовою.

Довгий прогін можна **зупинити й продовжити** з місця зупинки — розшифроване лишається. Платня за це одна:
після продовження `.srt` для цього файлу вже не складеться, бо таймкоди зшиваються лише наприкінці повного
прогону. Вікно про це попереджає заздалегідь.

## Що виходить із твоєї машини

Чесно і повністю:

| Крок | Куди йдуть дані |
|---|---|
| Транскрибація | Нікуди. Усе рахується у вікні застосунку, аудіо не залишає пристрій. |
| Читання звуку з файлу, експорт доріжки | Нікуди. Локальний ffmpeg, локальна тека. |
| **Завантаження моделі (один раз)** | Запит на `huggingface.co` — 286 МБ–1,5 ГБ ваг, залежно від моделі. Застосунок питає перед цим і не качає нічого без згоди. Твого контенту не передається. |
| **Конспект і таймкоди** | **Увесь транскрипт іде в команду `claude`, тобто в Anthropic.** |

Тобто «локально» — це про розшифровку, і це головне. Але кнопка конспекту передає текст назовні, і якщо ти
транскрибуєш зустріч із іншими людьми, то разом із текстом передаєш і їхні слова. Це свідомий вибір на одну
кнопку, а не фонова поведінка.

Телеметрії, аналітики, акаунтів і автооновлень немає жодних. Застосунок сам іде в мережу рівно один раз — по
модель, і лише після того, як ти натиснув «Завантажити» у вікні, де написано, скільки це важить.

## Вимоги

- **Linux x86_64.** Складання під Windows і macOS налаштоване, але ніколи не перевірялося.
- **ffmpeg** у `PATH` — застосунок не несе власного бінарника (чому — нижче). У дистрибутивах він є в пакетах:
  `sudo apt install ffmpeg`, `sudo dnf install ffmpeg`, `nix profile install nixpkgs#ffmpeg`.
  Без нього коротке відео чи аудіо (до 200 МБ) усе одно розшифрується — файл прочитає декодер самого браузера.
  Перевірено, що так читаються MP4, MOV, MKV, MP3, FLAC; AVI і WMV — ні. Збереження аудіодоріжки в OGG без
  ffmpeg не працює взагалі: кодувати Opus нічим.
- **Відеокарта з Vulkan** — не обов'язково, але без неї модель піде на CPU (wasm) і прогін буде в рази довшим.
- **`claude` CLI** — лише для конспекту й таймкодів. Решта працює без нього.
- від 300 МБ до 1,5 ГБ вільного місця під кеш моделі — залежно від того, яку вибрати.

## Моделі

Їх дві, і при першому запуску застосунок питає, яку завантажити — мовчки не качає нічого:

| Модель | Для чого | Розмір |
|---|---|---|
| [`onnx-community/whisper-small`](https://huggingface.co/onnx-community/whisper-small) | процесор або мало памʼяті — швидша, точність нижча | ≈ 286 МБ (391 МБ на карті з `shader-f16`) |
| [`onnx-community/whisper-large-v3-turbo`](https://huggingface.co/onnx-community/whisper-large-v3-turbo) | відеокарта — найточніша | ≈ 724 МБ (1,5 ГБ на карті з `shader-f16`) |

Обидві — ONNX-конверсії MIT-ліцензованого [`openai/whisper`](https://huggingface.co/openai/whisper-large-v3-turbo).
За замовчуванням пропонується та, що пасує машині: є відеокарта — turbo, немає — small. Поміняти модель або
видалити завантажену можна в налаштуваннях; після вибору ваги беруться з кешу й у мережу застосунок більше не
ходить.

Кеш лежить у `~/.config/transcriber/Service Worker/CacheStorage/`. Кнопка «Видалити» в налаштуваннях прибирає
звідти одну модель; усе разом зносить тека:

```bash
rm -rf ~/.config/transcriber/Service\ Worker/CacheStorage
```

Кеш партиціюється за origin, тому запакований застосунок і кожен dev-сервер тримають **власні** копії ваг. Якщо
тека несподівано важить кілька гігабайт — це воно.

## Збірка з вихідників

```bash
npm ci
npm start
```

На NixOS потрібна devShell з flake (`.envrc` підхоплює її через direnv, або `nix develop`): завантажений npm-ом
бінарник Electron зібраний під FHS, і бібліотеки йому підсовує nix-ld зі списку в `nix/electron-libs.nix`.

Встановити як застосунок у меню (NixOS):

```bash
npm run package && nix-build nix/magscribe.nix -o /tmp/magscribe-result && nix profile install /tmp/magscribe-result
```

Наступна збірка — це інший store path, тому перед повторним встановленням зроби `nix profile remove magscribe`.

Перевірки:

```bash
npx tsc --noEmit && npm run lint
```

## Чому ffmpeg системний, а не свій

Готові статичні збірки ffmpeg — GPLv3 (це нав'язують кодувальники x264/x265), а MagScribe тільки декодує звук і
кодує Opus, тобто нічого з того, через що вони GPL, не використовує. Розповсюджувати такий бінарник означало б
узяти на себе обов'язок публікувати відповідні вихідники ffmpeg і всіх статично злінкованих у нього бібліотек —
заради можливостей, які ніколи не викликаються. Системний ffmpeg — це копія користувача, і питання зникає.

Якщо ffmpeg у системі немає, застосунок скаже про це і запропонує відкрити сторінку завантаження — але
спершу спробує прочитати файл сам, декодером браузера (див. «Вимоги»).
