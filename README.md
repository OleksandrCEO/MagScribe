# MagScribe

Транскрибація відео й аудіо: текст, субтитри `.srt` і таймкоди розділів для YouTube.

> **In English.** MagScribe is a desktop app that transcribes video and audio with Whisper large-v3-turbo
> (WebGPU, wasm fallback). It produces plain text, SubRip subtitles and YouTube-style chapter timecodes. The
> interface speaks Ukrainian and English — it opens in the language of the operating system, and the settings
> window switches it. Linux x86_64; Windows x64 and macOS (Apple Silicon) builds are made but not yet tried on
> a real machine.

## Що воно робить

- кидаєш відео або аудіо — отримуєш текст;
- із того ж прогону — субтитри `.srt` із таймкодами;
- за бажанням — конспект і список розділів («00:00 — Назва») через команду `claude`;
- окремо — витягує аудіодоріжку в OGG/Opus (контейнер, який Telegram грає як голосове).

Інтерфейс — українською або англійською: при першому запуску береться мова системи, далі перемикається в
налаштуваннях.

Текст, субтитри й таймкоди можна виправити просто у вікні перед збереженням: Whisper плутає імена, а назви
розділів інколи варто переписати людською мовою.

Довгий прогін можна **зупинити й продовжити** з місця зупинки — розшифроване лишається. Платня за це одна:
після продовження `.srt` для цього файлу вже не складеться, бо таймкоди зшиваються лише наприкінці повного
прогону. Вікно про це попереджає заздалегідь.

## Вимоги

- **Linux x86_64.** Збірки під Windows x64 і macOS (Apple Silicon) складаються, але на живій машині ще не
  перевірялися. Вони не підписані: Windows SmartScreen попередить перед першим запуском, а завантажений на macOS
  застосунок відкриється лише після `xattr -cr /Applications/magscribe.app`.
- **ffmpeg** у `PATH` — застосунок не несе власного бінарника (чому — нижче). Поставити його:
  `sudo apt install ffmpeg`, `sudo dnf install ffmpeg`, `nix profile add nixpkgs#ffmpeg`, `winget install ffmpeg`,
  `brew install ffmpeg`. На macOS застосунок бере `PATH` із login shell користувача, тож ffmpeg із Homebrew і
  CLI для конспекту знаходяться, навіть коли MagScribe відкрито з Finder.
  Без нього коротке відео чи аудіо (до 200 МБ) усе одно розшифрується — файл прочитає декодер самого браузера.
  Перевірено, що так читаються MP4, MOV, MKV, MP3, FLAC; AVI і WMV — ні. Збереження аудіодоріжки в OGG без
  ffmpeg не працює взагалі: кодувати Opus нічим.
- **Відеокарта з Vulkan** — не обов'язково, але без неї модель піде на CPU (wasm) і прогін буде в рази довшим.
- **`claude` CLI** — лише для конспекту й таймкодів. Решта працює без нього.
- від 250 МБ до 1,5 ГБ вільного місця під кеш моделі — залежно від того, яку вибрати.

## Моделі

Їх дві, і при першому запуску застосунок питає, яку завантажити — мовчки не качає нічого:

| Модель | Для чого | Розмір |
|---|---|---|
| [`onnx-community/whisper-large-v3-turbo`](https://huggingface.co/onnx-community/whisper-large-v3-turbo) | **рекомендована** — найточніша; без відеокарти повільна | ≈ 724 МБ (1,5 ГБ на карті з `shader-f16`) |
| [`onnx-community/whisper-small`](https://huggingface.co/onnx-community/whisper-small) | швидша, якщо точність не критична або машина не тягне велику | ≈ 237 МБ на процесорі, 286 МБ на карті (391 МБ з `shader-f16`) |

Обидві — ONNX-конверсії MIT-ліцензованого [`openai/whisper`](https://huggingface.co/openai/whisper-large-v3-turbo).
За замовчуванням пропонується turbo — і на відеокарті, і на процесорі: на українській мові small плутає
терміни так, що текст уже не відредагуєш, не переслухавши запис. Поміняти модель або видалити завантажену
можна в налаштуваннях; після вибору ваги беруться з кешу.

Розмір залежить від машини, бо квантизація різна: turbo всюди йде в q4, small на процесорі — у int8 (менший
файл і помітно кращий результат, ніж 4 біти), а на відеокарті — у q4, бо для int8 у WebGPU-бекенді немає ядер
і прогін сповзає на CPU.

Кеш лежить у `~/.config/magscribe/Service Worker/CacheStorage/` (на macOS тека `magscribe` — у
`~/Library/Application Support/`, на Windows — у `%APPDATA%`). Кнопка «Видалити» в налаштуваннях прибирає
звідти одну модель; усе разом зносить тека:

```bash
rm -rf ~/.config/magscribe/Service\ Worker/CacheStorage
```

Кеш партиціюється за origin, тому запакований застосунок і кожен dev-сервер тримають **власні** копії ваг. Якщо
тека несподівано важить кілька гігабайт — це воно.

## Командний рядок

Той самий застосунок розшифровує файл без вікна, тож це може зробити скрипт або Claude Code:

```bash
magscribe --transcribe video.mp4 --format srt > video.srt
```

| Прапорець | Значення |
|---|---|
| `--transcribe <файл>` | що розшифрувати; відносний шлях рахується від поточної теки |
| `--format txt\|srt\|timed` | `txt` — суцільний текст (типово), `srt` — субтитри, `timed` — рядки `[00:00] текст`, з яких зручно робити розділи |
| `--lang uk\|en\|auto` | мова запису: `uk` (типово), `en`, або `auto` — рушій визначає сам |
| `--help` | довідка |

Результат іде в stdout, прогрес і помилки — у stderr. Код виходу: `0` — готово, `1` — розшифровка не вдалася,
`2` — неправильні аргументи або немає файла.

- Рушій розшифровки — той, що вибраний у вікні: модель із того самого кешу або API з тими самими адресою й
  ключем. **Командний рядок нічого не завантажує**: якщо моделі ще немає, він так і скаже — завантаж її один
  раз у вікні.
- Поки відкрите вікно MagScribe, команда відмовляється з помилкою: обидва режими ділять кеш і налаштування.
- Потрібна графічна сесія (Wayland або X), як і будь-якому Electron-застосунку; вікно при цьому не з'являється.
- Конспекту й розділів тут немає навмисно: той, хто викликав команду, зробить їх сам із `timed`-виводу.
- Звідки береться команда `magscribe`:
  - NixOS — пакет із `nix/magscribe.nix` кладе її в `PATH`;
  - deb / rpm — пакет створює `/usr/bin/magscribe`;
  - Windows — інсталятор кладе `magscribe.cmd` у `%LOCALAPPDATA%\magscribe\bin` і додає цю теку в `PATH`
    користувача; видалення застосунку прибирає її звідти. Термінал, відкритий до встановлення, її ще не бачить;
  - macOS — меню застосунку → «Встановити команду magscribe»: macOS спитає пароль і посилання ляже в
    `/usr/local/bin`.

## Збірка з вихідників

```bash
npm ci
npm start
```

На NixOS потрібна devShell з flake (`.envrc` підхоплює її через direnv, або `nix develop`): завантажений npm-ом
бінарник Electron зібраний під FHS, і бібліотеки йому підсовує nix-ld зі списку в `nix/electron-libs.nix`.

Встановити як застосунок у меню (NixOS):

```bash
npm run package && nix-build nix/magscribe.nix -o /tmp/magscribe-result && nix profile add /tmp/magscribe-result
```

Наступна збірка — це інший store path, тому перед повторним встановленням зроби `nix profile remove magscribe`.

Windows і macOS збираються на своїх ОС: `npm run make` кладе інсталятор Squirrel (Windows) або ZIP із `.app`
(macOS) в `out/make`. Без власної машини — workflow **Build** у GitHub Actions: він збирає Windows, macOS і Linux
(deb і rpm) і після публікації релізу сам додає файли до нього; запущений вручну
(`gh workflow run build.yml`) — лишає їх як artifacts.

Перевірки:

```bash
npx tsc --noEmit && npm run lint
```

## Чому ffmpeg системний, а не свій

Готові статичні збірки ffmpeg — GPLv3 (це нав'язують кодувальники x264/x265), а MagScribe тільки декодує звук і
кодує Opus, тобто нічого з того, через що вони GPL, не використовує. Розповсюджувати такий бінарник означало б
узяти на себе обов'язок публікувати відповідні вихідники ffmpeg і всіх статично злінкованих у нього бібліотек —
заради можливостей, які ніколи не викликаються. Системний ffmpeg — це копія користувача, і питання зникає.

Якщо ffmpeg у системі немає, застосунок скаже про це і запропонує відкрити сторінку завантаження — але
спершу спробує прочитати файл сам, декодером браузера (див. «Вимоги»).
