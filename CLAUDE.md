# MagScribe

Local-first desktop app: converts video/audio files and transcribes them. Everything runs on the user's machine — no cloud upload, no external transcription API.

**Stack**: Electron 44 / electron-forge 7 (vite plugin) / Vite 5 / React 19 / TypeScript 5 / Tailwind CSS v4 / shadcn/ui (Base UI variant) / npm

## Architecture map

- `src/main.ts` — Electron main process. All filesystem, ffmpeg and transcription work belongs here, never in the renderer.
- `src/preload.ts` — the only bridge to the renderer. Expose narrow APIs via `contextBridge`; `nodeIntegration` stays off.
- `src/renderer.tsx` → `src/App.tsx` — React entry and UI root.
- `src/components/ui/` — shadcn components, generated by the CLI. Add with `npx shadcn@latest add <name>`; do not hand-write them.
- `src/lib/utils.ts` — re-exports `cn` (from the `cn` package). Use it for class merging, never write a local classnames helper.
- `src/index.css` — Tailwind entry + shadcn theme tokens.
- Three separate Vite configs: `vite.main.config.ts`, `vite.preload.config.ts`, `vite.renderer.config.mts`. Targets are wired in `forge.config.ts`.

## Commands

- `npx tsc --noEmit` — typecheck (run after every code change)
- `npm run lint` — eslint (run after every code change)
- `npx shadcn@latest add <component>` — add a shadcn component
- `npm start` — dev run (Vite + Electron window); the developer runs this, ask before launching it yourself
- On NixOS the commands above need the flake devShell (`.envrc` loads it via direnv, or `nix develop`): the npm-downloaded Electron binary is unpatched and nix-ld feeds it the libraries listed in `flake.nix`

## Gotchas

- The renderer config MUST stay `.mts`. `@tailwindcss/vite` is ESM-only and Forge loads a `.ts` config as CJS — renaming it back breaks `npm start` with an opaque esbuild error.
- The `@/` alias is declared twice: `paths` in `tsconfig.json` and `resolve.alias` in `vite.renderer.config.mts`. Change both or imports break in either tsc or the bundle.
- `@vitejs/plugin-react` is pinned to `^4` — v6+ requires Vite 8, Forge is on Vite 5. Do not bump it.
- Theme: CSS knows only `prefers-color-scheme` (`@custom-variant dark (@media (prefers-color-scheme: dark))` in `src/index.css`, tokens under `@media (prefers-color-scheme: dark) { :root }`). The light/system/dark toggle in `App.tsx` works by sending `theme:set` to main, which flips `nativeTheme.themeSource` — Chromium then reports the matching `prefers-color-scheme`. No `.dark` class, no theme provider, no `next-themes`.
- `src/audio.ts` also has `exportAudio(filePath)` — re-encodes to OGG/Opus in the temp folder; only one export lives at a time and `audio:save` copies out nothing but that file.
- Re-running `shadcn init` or re-adding a component overwrites `src/index.css` and `src/components/ui/*` — the system-dark block and `theme="system"` in `sonner.tsx` must be re-applied afterwards.
- shadcn base color is `neutral`; the current CLI palette is neutral/zinc/stone/mauve/olive/mist/taupe (`slate` and `gray` no longer exist).
- Long-running jobs (ffmpeg, transcription) must run in the main process and report progress to the renderer over IPC. Blocking the renderer freezes the window.
- `npm start` passes `--force-device-scale-factor=1` on purpose: on KDE Wayland the display scale is counted twice (`devicePixelRatio` 4 on a scale-2 monitor) and the window renders ~4x too large. Keep the flag; a packaged build needs the same flag from its launcher.
- The Vite plugin strips `node_modules` from the package: a built asar holds only `.vite/*` and `package.json`. Runtime binaries and assets therefore go through `packagerConfig.extraResource` (like the ffmpeg binary) and are read from `process.resourcesPath`, never `require`d from a package. `asar.unpack` would have nothing to unpack.
- `src/summary.ts` — runs the local `claude` CLI (`execFile`, transcript on stdin, 120 s cap) over a transcript; the whole instruction lives in `SUMMARY_PROMPT`, edit it there.
- `src/worker.ts` — the transcription Web Worker. It refuses software WebGPU adapters (SwiftShader) and falls to wasm instead, and the `ready` message carries the real adapter name for the status line. The old "int8 is ~9x slower than q4" measurement was taken on SwiftShader, i.e. on the CPU; nothing about GPU dtypes has been measured on a real GPU yet.
- `src/audio.ts` — `extractAudio(filePath)` decodes any media file to 16 kHz mono `Float32Array` via the ffmpeg-static binary. Reuse it instead of spawning ffmpeg again.
- **WebGPU on NixOS needs `/etc/vulkan/icd.d/nvidia_icd.json` with `library_path` set to the bare soname
  `libGLX_nvidia.so.0`.** Chromium's GPU sandbox (`content/common/gpu_pre_sandbox_hook_linux.cc`) lets the GPU
  process read only `/usr/share/vulkan/icd.d` and `/etc/vulkan/icd.d`, never `/nix/store` or `/run/opengl-driver`,
  and it dlopens the driver by soname before the sandbox starts. The nixpkgs manifest points at an absolute store
  path, so inside the sandbox the loader finds no driver and Dawn silently takes SwiftShader (CPU): `requestAdapter()`
  still succeeds, `shader-f16` is missing, and the GPU process burns 600 % CPU. The manifest is provided by the host
  config (`/home/config/modules/desktop/nvidia.nix`); the flake still needs `vulkan-loader` for `libvulkan.so.1`.
  The only trustworthy check is `nvidia-smi` by PID: our GPU process must be `C+G` with hundreds of MiB, not `G` with
  3 MiB. The full evidence and wrong turns live in git history (`docs/gpu-handoff.md` up to commit `1b9df89`). `ozone-platform=x11` does not help and wrecks
  HiDPI; do not retry it.
- A run that sits at 0 % for many minutes with the GPU process (not the renderer) at ~500 % CPU was SwiftShader JIT-compiling shaders on the CPU; on a real GPU the first run still compiles, but not for that long. Chromium's per-cache 6 MB cap on `DawnWebGPUCache` is real and `gpu-disk-cache-size-kb` in `main.ts` raises it, but the cache only helps once the adapter is a real GPU. Diagnose with `ps -T -p <gpu pid>`: threads named `Thread<NN>` are SwiftShader's workers.
- During a transcription do not touch `src/`: Forge restarts Electron on every main/preload change and Vite reloads the renderer on every renderer change, either of which kills the run and, on a first run, leaves the shader cache unwritten. `.direnv` is excluded from Vite's watcher in `vite.renderer.config.mts` for the same reason.
- `Notification.isSupported()` is false without `libnotify` on the library path — Electron dlopens it at runtime. The dev shell provides it; a packaged build needs it from the host system.
- Dropped files have no `File.path` in modern Electron. The real path comes from `window.api.getPathForFile(file)`, which wraps `webUtils.getPathForFile` in the preload.
- Toasts: `import { toast } from 'sonner'`. `<Toaster />` is mounted once in `App.tsx` — don't mount a second one.
