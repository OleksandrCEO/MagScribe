# MagScribe

Local-first desktop app: converts video/audio files and transcribes them. Everything runs on the user's machine — no cloud upload, no external transcription API.

**Stack**: Electron 44 / electron-forge 7 (vite plugin) / Vite 5 / React 19 / TypeScript 5 / Tailwind CSS v4 / shadcn/ui (Base UI variant) / npm

## Architecture map

- `src/main.ts` — Electron main process. All filesystem, ffmpeg and transcription work belongs here, never in the renderer.
- `src/preload.ts` — the only bridge to the renderer. Expose narrow APIs via `contextBridge`; `nodeIntegration` stays off.
- `src/renderer.tsx` → `src/App.tsx` — React entry and UI root.
- `src/components/ui/` — shadcn components, generated by the CLI. Add with `npx shadcn@latest add <name>`; do not hand-write them.
- `src/lib/utils.ts` — re-exports `cn` (from the `cn` package). Use it for class merging, never write a local classnames helper.
- `src/index.css` — Tailwind entry + shadcn theme tokens.
- Three separate Vite configs: `vite.main.config.ts`, `vite.preload.config.ts`, `vite.renderer.config.mts`. Targets are wired in `forge.config.ts`.

## Commands

- `npx tsc --noEmit` — typecheck (run after every code change)
- `npm run lint` — eslint (run after every code change)
- `npx shadcn@latest add <component>` — add a shadcn component
- `npm start` — dev run (Vite + Electron window); the developer runs this, ask before launching it yourself

## Gotchas

- The renderer config MUST stay `.mts`. `@tailwindcss/vite` is ESM-only and Forge loads a `.ts` config as CJS — renaming it back breaks `npm start` with an opaque esbuild error.
- The `@/` alias is declared twice: `paths` in `tsconfig.json` and `resolve.alias` in `vite.renderer.config.mts`. Change both or imports break in either tsc or the bundle.
- `@vitejs/plugin-react` is pinned to `^4` — v6+ requires Vite 8, Forge is on Vite 5. Do not bump it.
- Dark theme is **system-driven only**: `@custom-variant dark (@media (prefers-color-scheme: dark))` in `src/index.css`, tokens under `@media (prefers-color-scheme: dark) { :root }`. There is no `.dark` class and no theme provider. Never add `next-themes` or a theme toggle unless asked.
- Re-running `shadcn init` or re-adding a component overwrites `src/index.css` and `src/components/ui/*` — the system-dark block and `theme="system"` in `sonner.tsx` must be re-applied afterwards.
- shadcn base color is `neutral`; the current CLI palette is neutral/zinc/stone/mauve/olive/mist/taupe (`slate` and `gray` no longer exist).
- Long-running jobs (ffmpeg, transcription) must run in the main process and report progress to the renderer over IPC. Blocking the renderer freezes the window.
- `npm start` passes `--force-device-scale-factor=1` on purpose: on KDE Wayland the display scale is counted twice (`devicePixelRatio` 4 on a scale-2 monitor) and the window renders ~4x too large. Keep the flag; a packaged build needs the same flag from its launcher.
- Toasts: `import { toast } from 'sonner'`. `<Toaster />` is mounted once in `App.tsx` — don't mount a second one.
