# MagScribe

Desktop app: converts video/audio files and transcribes them. The transcription and the summary are swappable engines — `docs/concept.md` holds the idea, `docs/engines.md` the plan. **Copy is neutral**: UI strings, README, package and desktop descriptions say what the app does (transcription, subtitles, chapters) and never where it runs — no «local», «on your machine», «what leaves your machine», no privacy tables. The app is universal, not local; such a promise would have to be rewritten with every new engine.

**Stack**: Electron 44 / electron-forge 7 (vite plugin) / Vite 5 / React 19 / TypeScript 5 / Tailwind CSS v4 / shadcn/ui (Base UI variant) / npm

## Architecture map

- `src/main.ts` — Electron main process. All filesystem, ffmpeg and transcription work belongs here, never in the renderer.
- `src/preload.ts` — the only bridge to the renderer. Expose narrow APIs via `contextBridge`; `nodeIntegration` stays off.
- `src/renderer.tsx` → `src/App.tsx` — React entry and UI root.
- `src/components/ui/` — shadcn components, generated by the CLI. Add with `npx shadcn@latest add <name>`; do not hand-write them.
- `src/subtitles.ts` — timecodes and segments: the `Segment` type itself, `timecode`/`toSrt`/`toTimedText`, `toSegments` (normalises what Whisper hands back) and `parseClock` (reads ffmpeg's `Duration:`). The two last ones live here rather than in `worker.ts`/`audio.ts` because those cannot be imported outside a worker or without electron — and these are the functions `src/subtitles.test.ts` covers.
- `src/cli.ts` + `src/headless.ts` — the command line (`--transcribe <file> --format txt|srt|timed --lang uk|en|auto`). `cli.ts` parses argv and renders the output (no electron imports; `src/cli.test.ts`); main runs the job in a hidden `BrowserWindow` on `index.html#cli`, where `renderer.tsx` loads `headless.ts` instead of React, because the model needs the window's Chromium (WebGPU, Cache Storage on the same origin). Result to stdout, progress to stderr over `cli:*` channels that main registers only in this mode. The worker gets `offline: true` and never downloads. Both modes take `requestSingleInstanceLock`, so the CLI refuses while a window is open.
- `src/models.ts` — the two Whisper checkpoints the window offers (small for the CPU, large-v3-turbo for a real
  card), their approximate download sizes per dtype path, and the Cache Storage helpers that say which one is on
  disk and delete one of them. No node, React or electron imports: the worker reads it too.
- `src/gpu.ts` — `findGpu()`, the one adapter probe. The window calls it before anything is downloaded (to pick
  the model and show its real size), the worker calls it to choose device and dtype; `requestAdapter()` reads the
  driver without creating a device, so asking twice is free.
- `src/i18n.ts` — every line the app shows, in Ukrainian and English. Two dictionaries plus `const en: typeof uk`, so a forgotten key is a type error; values that take a number or a name are functions, and `*emphasis*` / `` `code` `` inside a line is rendered by `rich()` in `settings.tsx`. Keep it free of node and React imports — main, the worker and the renderer all import it. The renderer reads `STRINGS[uiLang]`; main and the worker read `t()` after a `setUiLang()` (over `lang:set`, and with the worker's `load` message).
- `src/settings.tsx` — the shared modal shell (a native `<dialog>`), the windows built on it (settings with the language picker, About, the confirmations), `rich()` for the markup inside a translated line, and the localStorage helpers behind the theme, the language and the prompts.
- `docs/concept.md` — where the product is going: swappable engines for both the transcription and the summary. `docs/engines.md` — the phased plan for the API engines and what each phase has done.
- `src/lib/utils.ts` — re-exports `cn` (from the `cn` package). Use it for class merging, never write a local classnames helper.
- `src/index.css` — Tailwind entry + shadcn theme tokens.
- Three separate Vite configs: `vite.main.config.ts`, `vite.preload.config.ts`, `vite.renderer.config.mts`. Targets are wired in `forge.config.ts`.

## Commands

- `npx tsc --noEmit` — typecheck (run after every code change)
- `npm run lint` — eslint 9, flat config in `eslint.config.mjs` (run after every code change)
- `npm test` — `node --test` over the pure functions; it runs `.ts` through node's own type stripping, which is why the test file imports `./subtitles.ts` with the extension (`allowImportingTsExtensions` in `tsconfig.json`)
- `npx shadcn@latest add <component>` — add a shadcn component
- `magick -background none assets/icon.svg -depth 8 assets/icon.png && magick -background none assets/icon.svg -define icon:auto-resize=256,128,64,48,32,16 assets/icon.ico` — regenerate the icons after editing `assets/icon.svg` (the master; never hand-edit the raster)
- `npm start` — dev run (Vite + Electron window); the developer runs this, ask before launching it yourself
- `npm run package && nix-build nix/magscribe.nix -o /tmp/magscribe-result` — build the installable app, then `nix profile add /tmp/magscribe-result` puts MagScribe in the application menu (`install` is a deprecated alias and warns). A later build is a store path of its own, so replace it with `nix profile remove magscribe` first. See `nix/magscribe.nix`
- On NixOS the commands above need the flake devShell (`.envrc` loads it via direnv, or `nix develop`): the npm-downloaded Electron binary is unpatched and nix-ld feeds it the libraries listed in `nix/electron-libs.nix`

## Release

The flake's `packages.default` is what a NixOS config installs (`inputs.magscribe.url = "github:OleksandrCEO/MagScribe"`). It fetches the electron-forge output from the GitHub release `v<version>`, so a release is:

1. bump `package.json`, then `npm run package`;
2. `tar -C out --sort=name --owner=0 --group=0 --numeric-owner --mtime=2026-01-01 -czf /tmp/agent/magscribe-<version>-linux-x64.tar.gz magscribe-linux-x64`;
3. `nix hash convert --hash-algo sha256 --to sri $(nix-prefetch-url --unpack file:///tmp/agent/magscribe-<version>-linux-x64.tar.gz)` → the `hash` in `flake.nix`;
4. commit and push, then — only when the developer says so — tag `v<version>`, push the tag, and `gh release create v<version> <tarball>`.

The tarball must be the one the hash was taken from: rebuilding gives different bytes. Before the release exists, test the flake with `nix store add --name source <unpacked magscribe-linux-x64>` (that is the fixed-output path `fetchzip` would produce) and `nix build path:.#default --override-input nixpkgs github:nixos/nixpkgs/<rev from /home/config/flake.lock>`.

## Gotchas

- The renderer config MUST stay `.mts`. `@tailwindcss/vite` is ESM-only and Forge loads a `.ts` config as CJS — renaming it back breaks `npm start` with an opaque esbuild error.
- The `@/` alias is declared twice: `paths` in `tsconfig.json` and `resolve.alias` in `vite.renderer.config.mts`. Change both or imports break in either tsc or the bundle.
- `@vitejs/plugin-react` is pinned to `^4` — v6+ requires Vite 8, Forge is on Vite 5. Do not bump it.
- Theme: CSS knows only `prefers-color-scheme` (`@custom-variant dark (@media (prefers-color-scheme: dark))` in `src/index.css`, tokens under `@media (prefers-color-scheme: dark) { :root }`). The light/system/dark toggle in `App.tsx` works by sending `theme:set` to main, which flips `nativeTheme.themeSource` — Chromium then reports the matching `prefers-color-scheme`. No `.dark` class, no theme provider, no `next-themes`.
- `src/audio.ts` also has `exportAudio(filePath)` — re-encodes to OGG/Opus in the temp folder; only one export lives at a time and `audio:save` copies out nothing but that file.
- Re-running `shadcn init` or re-adding a component overwrites `src/index.css` and `src/components/ui/*` — the system-dark block and `theme="system"` in `sonner.tsx` must be re-applied afterwards.
- shadcn base color is `neutral`; the current CLI palette is neutral/zinc/stone/mauve/olive/mist/taupe (`slate` and `gray` no longer exist).
- Long-running jobs (ffmpeg, transcription) must run in the main process and report progress to the renderer over IPC. Blocking the renderer freezes the window.
- `npm start` passes `--force-device-scale-factor=1` on purpose: on KDE Wayland the display scale is counted twice (`devicePixelRatio` 4 on a scale-2 monitor) and the window renders ~4x too large. Keep the flag; a packaged build needs the same flag from its launcher.
- The Vite plugin strips `node_modules` from the package: a built asar holds only `.vite/*` and `package.json`. Runtime binaries and assets therefore go through `packagerConfig.extraResource` (like the ffmpeg binary) and are read from `process.resourcesPath`, never `require`d from a package. `asar.unpack` would have nothing to unpack.
- `src/summary.ts` — the summary engines behind one `ai:run` channel keyed by `AI_TASKS`: the `claude` CLI (`execFile`, transcript on stdin) or an OpenAI-compatible `/chat/completions`; 300 s cap and `cancelAi` for both. Which one is read from `src/aiSettings.ts` on every run.
- `src/apiRequest.ts` — `postApi`, the one POST to the OpenAI-compatible API (`net.fetch`, stored key, `redirect: 'error'`, timeout, readable errors) and `cancelApi`. The summary and the transcription both go through it; never write a second fetch.
- `src/speech.ts` — the API transcription engine in main (`speech:run`): one piece of samples → Opus via ffmpeg (WAV without it) → `/audio/transcriptions` with `verbose_json` → `Segment[]`. A model that sends no segments is an error, not a transcript without subtitles. `src/useApiSpeech.ts` is its renderer half with the same `transcribe` as `useWhisper`: `splitAtSilence` (`src/pcm.ts`) cuts the recording into ≤10-minute pieces at pauses, timestamps are shifted by the piece's start, a stop goes through `cancelAi`.
- `src/aiSettings.ts` — main-only: both engine choices (`engine` for the summary, `speech` for the transcription), the shared base URL, a model for each, in `userData/engines.json`; the key encrypted with `safeStorage` (refused on `basic_text`, i.e. no keyring) and never sent to the renderer. A new base URL drops the stored key. `src/api.ts` holds the pure half — URL and update validation, request body, reply and segment parsing — covered by `src/api.test.ts`.
- `src/useWhisper.ts` — the local Whisper engine as a hook: model choice, download consent, the worker, and `transcribe()` returning `Promise<{ text, segments } | null>` (null = stopped or GPU gone). `App.tsx` keeps only the run itself and picks `useWhisper` or `useApiSpeech` by the `speech` setting, re-read whenever the settings window closes.
- `src/prompts.ts` — the two instructions themselves and their storage keys. The settings window edits them and the renderer sends the edited text with the call, so what is here is the fallback. Keep it free of node imports: the renderer imports this module.
- Transcription always runs with `return_timestamps: true`, so one run feeds the transcript, the .srt and the chapters; the `result` message carries `segments` next to the text. Whisper leaves the end of an unclosed chunk `null` despite what the types say — `toSegments` in `src/worker.ts` normalises that.
- **`return_timestamps` also changes the decoding path**: `WhisperForConditionalGeneration.generate` then takes `_generate_with_seek`, a loop that re-encodes and generates again whenever the model stops short inside a 30-second window. So one window costs one `generate()` or several, `on_finalize` fires per pass and not per window, and a run is slower than the plain chunked path. Never derive progress from counting passes, nor from summing the timestamps they stop at (a repeat pass runs on padded silence and Whisper stamps it up to 30 s, so that sum also ran ahead — the bar sat at 100 % for minutes on a 2-hour file). `src/worker.ts` wraps `model.generate`, which the pipeline calls exactly once per window (the passes go through `super.generate` inside it), and counts finished windows; `done * JUMP_S` is also what a stopped run resumes from. Passing `max_new_tokens` would skip the seek loop and make it fast again, at the cost of dropping the tail of a window the model gave up on.
- `src/worker.ts` — the transcription Web Worker. It refuses software WebGPU adapters (SwiftShader) and falls to wasm instead, and the `ready` message carries the real adapter name for the status line. The old "int8 is ~9x slower than q4" measurement was taken on SwiftShader, i.e. on the CPU; nothing about GPU dtypes has been measured on a real GPU yet.
- `src/audio.ts` — `extractAudio(filePath)` decodes any media file to 16 kHz mono `Float32Array` via the ffmpeg-static binary. Reuse it instead of spawning ffmpeg again.
- **WebGPU on NixOS needs `/etc/vulkan/icd.d/nvidia_icd.json` with `library_path` set to the bare soname
  `libGLX_nvidia.so.0`.** Chromium's GPU sandbox (`content/common/gpu_pre_sandbox_hook_linux.cc`) lets the GPU
  process read only `/usr/share/vulkan/icd.d` and `/etc/vulkan/icd.d`, never `/nix/store` or `/run/opengl-driver`,
  and it dlopens the driver by soname before the sandbox starts. The nixpkgs manifest points at an absolute store
  path, so inside the sandbox the loader finds no driver and Dawn silently takes SwiftShader (CPU): `requestAdapter()`
  still succeeds, `shader-f16` is missing, and the GPU process burns 600 % CPU. The manifest is provided by the host's
  own NixOS configuration (its `nvidia.nix`), not by this repository; the flake still needs `vulkan-loader` for
  `libvulkan.so.1`.
  The only trustworthy check is `nvidia-smi` by PID: our GPU process must be `C+G` with hundreds of MiB, not `G` with
  3 MiB. The full evidence and wrong turns live in git history (`docs/gpu-handoff.md` up to commit `1b9df89`). `ozone-platform=x11` does not help and wrecks
  HiDPI; do not retry it.
- The model cache is Chromium's Cache Storage, and with it localStorage (theme, language, model, prompts), is partitioned per origin. Both the packaged app and a dev run are on `app://bundle`: in dev, `serveDev` in `main.ts` answers that scheme from the Vite server, so the two share the model and the settings. Before that, every dev port was an origin of its own with its own ~750 MB copy of the weights. Check with `du -sh ~/.config/magscribe/Service\ Worker/CacheStorage/*`.
- Whichever `libvulkan.so.1` Electron ends up loading decides whether WebGPU sees the card, because the ICD search directory is compiled into the loader. Electron's own copy (next to the binary, reached through `$ORIGIN`) keeps the upstream `/etc` default and finds `/etc/vulkan/icd.d/nvidia_icd.json`, the one manifest Chromium's GPU sandbox allows. nixpkgs' `vulkan-loader` is built with `SYSCONFDIR=/run/opengl-driver/share`, whose manifests all point into `/nix/store` — the sandbox refuses those and the loader reports `Found no drivers`. So never put `vulkan-loader` ahead of the app's own directory in a packaged build's RUNPATH. `grep -ao '/etc\|/run/opengl-driver/share' <loader>` tells the two apart in a second.
- Never judge the GPU from a run started inside Claude's shell. That shell is an FHS sandbox with its own tmpfs `/etc` (the host's is read-only at `/.host-etc`), and it carries no `vulkan` entry, so Dawn there always reports `vkCreateInstance: Found no drivers!` and falls back to SwiftShader no matter how healthy the host is. Check `/.host-etc/vulkan/icd.d/nvidia_icd.json` for the real state, and let the developer run the app from their own session.
- A run that sits at 0 % for many minutes with the GPU process (not the renderer) at ~500 % CPU was SwiftShader JIT-compiling shaders on the CPU; on a real GPU the first run still compiles, but not for that long. Chromium's per-cache 6 MB cap on `DawnWebGPUCache` is real and `gpu-disk-cache-size-kb` in `main.ts` raises it, but the cache only helps once the adapter is a real GPU. Diagnose with `ps -T -p <gpu pid>`: threads named `Thread<NN>` are SwiftShader's workers.
- During a transcription do not touch `src/`: Forge restarts Electron on every main/preload change and Vite reloads the renderer on every renderer change, either of which kills the run and, on a first run, leaves the shader cache unwritten. `.direnv` is excluded from Vite's watcher in `vite.renderer.config.mts` for the same reason.
- **int8 has no WebGPU kernels, and the status line cannot tell you that.** onnxruntime's WebGPU backend runs q4
  natively (`MatMulNBits`) but has nothing for the int8 integer matmuls, so those nodes execute on the CPU inside
  the GPU session, with tensors copied across every layer. Measured on an RTX card: `WebGPU` in the status, GPU at
  8–30 %, CPU at ~20 %, and a file that turbo q4 does in 35 s crawling for minutes. The status line names the
  adapter the session was created with — not where the operators ended up. This is why `src/models.ts` keys the
  quantisation by runtime as well as by model: small is int8 on wasm and q4 on a card.
- **`powerSaveBlocker` is a no-op on Wayland unless a window is focused.** Chromium's Wayland backend hangs the
  inhibitor off the focused surface (`zwp_idle_inhibit_manager`: «Cannot inhibit going idle when no window is
  focused»), while `powerSaveBlocker.isStarted()` still answers `true` — measured on KDE/Wayland, nothing showed
  up in `systemd-inhibit --list` or in PowerDevil's `ListInhibitions`. An unattended hour-long run with the
  window minimised is exactly the case that matters, so `src/main.ts` also holds a logind inhibitor for the
  duration: `systemd-inhibit --what=idle:sleep --mode=block … cat`, whose stdin is our pipe, so the inhibitor
  dies with the app even on a crash. Check it with `systemd-inhibit --list | grep MagScribe` during a run.
- `Notification.isSupported()` is false without `libnotify` on the library path — Electron dlopens it at runtime. The dev shell provides it; a packaged build needs it from the host system.
- Dropped files have no `File.path` in modern Electron. The real path comes from `window.api.getPathForFile(file)`, which wraps `webUtils.getPathForFile` in the preload.
- Packaging is two steps on purpose: `npm run package` needs the network and a writable `node_modules`, so Nix only wraps what electron-forge already produced (`out/magscribe-linux-x64`). `nix/magscribe.nix` patchelfs those FHS binaries against the same library list the dev shell uses, adds `/run/opengl-driver/lib` and the `--force-device-scale-factor=1` flag to the launcher, and ships a desktop entry. Everything Chromium only dlopens (libglvnd for `libEGL.so.1`, libnotify, the Vulkan loader) has to be listed in `runtimeDependencies` — autoPatchelfHook cannot see those, and without libglvnd the GPU process fails every EGL display type and exits.
- `productName` (`magscribe`) names three things at once: the Wayland app_id, which KDE matches against the desktop entry `magscribe.desktop` in `nix/magscribe.nix`; the data folder `~/.config/magscribe`, where the model and the settings live; and the binary in `out/magscribe-linux-x64`. Renaming it moves all three — the data folder included, so the model would be downloaded again.
- Toasts: `import { toast } from 'sonner'`. `<Toaster />` is mounted once in `App.tsx` — don't mount a second one.

## Git

- **Claude runs git in this project, fully**: commits, branches, merges, rebases of its own unpushed work, push to
  `origin`. No need to ask first, and no need to wait for a trigger.
- **Commit a finished piece of work, not every edit.** One logical change per commit — a feature, a fix, a docs
  pass — so the history reads well. Several small tweaks in a row go into one commit, not five.
- Commit format: `scope: description` (e.g. `window: restore size and position on launch`).
- **Version: one commit, one patch.** `package.json` holds `0.x.y`; bump `y` by one in the same commit, and
  roll the tenth into the next minor (`0.7.9` → `0.8.0`), so a minor reads as «ten improvements». Nothing
  else carries a version: `nix/magscribe.nix` and the About window both read this field. `1.0.0` comes when
  the app is actually released, not before.
- **A release is the developer's call**: the tag `v<version>` and `gh release create` publish a build that the
  flake installs from, so they wait for the developer's word (see Release above). Pushing commits does not.
- Never rewrite history that is already on `origin` (no force-push to `main`).
